## HUNT ITEMS

### (a) Hardcoded model/provider strings where live data was required — CLEAR
The model chip reads `supervisorBinding(supervisorConfig, supervisorAgent)`
(`apps/web/src/components/agents/conductor.ts:198-208`), which is built from:
- `supervisorAgent` = `catalog?.agents.find(a => a.key === "orchestration")` (live `fetchCatalog()`,
  `page.tsx:557-560`)
- `supervisorConfig` = `fetchAgentConfig("orchestration")` (live `GET /agents/config/orchestration`,
  `page.tsx:317-330`, pre-existing endpoint at `apps/web/src/components/agents/api.ts:341`)

Until both resolve, the chip renders `BINDING_UNREAD_TEXT = "model binding not read yet"`
(`conductor.ts:211`), never the ADR's example string `claude-opus-4-8`. Verified in
`conductor-logic.test.ts` (`"follows a different live binding instead of the ADR's example"`,
line 236 of `conductor-band.test.tsx`) and confirmed passing in my own re-run (below).
`providerFromModelId()` (`conductor.ts:183-189`) implements the exact billing-separation rule
from the brief — `/` in id ⇒ `openrouter`, bare `claude-*` ⇒ `anthropic` — and defers to the
server for anything else rather than guessing. **No violation.**

### (b) Fake/optimistic run states — CLEAR
`useRunEverything` (`use-run-everything.ts`) only ever reaches `phase: "running"` after a real
202/`accepted.planId` (or a 409's `planId`), and only reaches `"settled"` when a **polled**
`RunPlanRecord.status` is terminal (`isTerminalPlanStatus`, `orchestrationPlan.ts:143-145`). The
first press of "Run everything" opens a confirmation dialog and dispatches nothing
(`ConductorBand.tsx` — `onClick={() => setConfirmOpen(true)}` at the header button, `confirmAndRun`
only fires on the modal's "Start the plan" button). A transient poll failure does not fabricate a
terminal state — the last known record stands and the transport error is shown alongside it
(`use-run-everything.ts:163-171`). **No violation.**

### (c) Plan view rendering stale/empty data silently — CLEAR
`groupPlanByWorkflow` places any plan card whose agent no *loaded* map places into `unplaced`
rather than guessing a group (`conductor.ts:377-406`, tested by
`conductor-band.test.tsx` plan-view group). The status strip explicitly renders "Plan not read
yet" / the raw `planError` text when `plan` is null (`ConductorBand.tsx:296-303`), rather than
stale numbers. `page.tsx`'s `loadPlan()` explicitly nulls `orchestrationPlan` on any fetch error
rather than leaving a stale plan on screen (`page.tsx:296-311`). **No violation.**

### (e) Design-system violations vs B1/B2/B3 standard — **ONE VIOLATION FOUND**
`ConductorBand.tsx:328` uses `border-state-err/40 bg-state-err/10` for the run-status banner's
"error"/"halted" tone. **`state-err` is not a defined color token.**
`apps/web/tailwind.config.ts:53-60` defines `state.ok`, `state.warn`, `state.danger`,
`state.info`, `state.neutral`, `state.degraded` — there is no `state.danger` alias named `err`.


**Effect**: the halted/failed/"the plan did not start" run-status banner — the single most
safety-critical honest-failure-signalling element in this component — silently loses its
red-tinted border and background. It falls back to whatever the browser default border-color
resolves to. The text content is still correct (this is why no vitest assertion catches it —
they all test `textContent`, never computed style), but the visual severity cue that the rest of
the component is otherwise careful to provide (`state-ok`/`state-warn` both work correctly) is
silently absent for the error path.

A second, lower-severity instance of the same class of bug: `ConductorBand.tsx:590` uses

uses the semantic `text-aether-green` (line 588). This one **does** render (Tailwind ships a
default `red` palette so `red-300` resolves), but it breaks the "semantic tokens only for
status colour" discipline `tailwind.config.ts:47-51`'s own comment establishes as a "load-bearing
Rule D-1" for exactly this class of state colour.

**MUST-FIX**: `apps/web/src/components/agents/ConductorBand.tsx:328` — replace `state-err` with
the actual defined token `state-danger` (i.e. `border-state-danger/40 bg-state-danger/10`).
**SHOULD-FIX**: `apps/web/src/components/agents/ConductorBand.tsx:590` — replace `text-red-300`
